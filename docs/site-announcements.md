# 网站公告维护

公告内容在 `src/data/announcements.js`，随静态网站一起构建发布，不依赖晨报生成电脑或后台服务。

- 新增公告时使用唯一、稳定的 `id`，提供 `zh` / `en` 的标题、摘要和正文，`date` 填实际发布日期。
- `category` 为 `service`（服务通知）或 `feature`（功能更新）。列表先显示置顶项，其余按日期倒序，同日保持文件中的顺序。
- `pinned: true` 置顶；`banner: true` 显示顶部横幅。若有多条横幅，先显示排序最靠前、且未被当前读者关闭的一条。
- 新公告默认计入未读。补录历史更新使用 `notify: false`，避免将旧功能全部当作新消息。
- 已读与横幅关闭状态分别保存在当前浏览器。读过公告不会自动关闭横幅，关闭横幅后仍可从铃铛查看。
- 修改重要安排时发布新的公告并使用新 ID，让读者收到新的未读提醒；同时移除旧安排的 `banner` / `pinned`，并在旧正文中注明安排已更新。
- 1 月暂停通知暂不承诺具体日期。确定起止时间或恢复发布时更新公告记录；恢复后撤下暂停横幅。

提交源代码后执行 `npm run deploy` 发布。公告只有在重新部署后才会更新；已发布的页面和历史晨报不会因为生成电脑关机而消失。
